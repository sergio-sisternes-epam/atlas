Atlas gives your agent or skill a second brain.
The brain follows a defined structure, and it can connect to other brains.
Knowledge lives in git as markdown pages.
A SCHEMA and a deterministic Python CLI check the shape of every page.
Atlas works with any git-capable agent harness that the APM CLI can target.

| Property | What it is |
| --- | --- |
| Git-based | Stores mount as git submodules in the project. |
| Guardrailed | The SCHEMA and the CLI `compile` command check shape, frontmatter and links. |
| Distributed | Pages link across stores with `atlas://` links. |
| Clustered | Knowledge groups into logical clusters, such as work hubs. |
| Shared or dedicated | Knowledge lives on the consumer branch `atlas`, or in a separate store repository. |
| Recall | Search is `grep` by default. The ranked profile `atlas:ranked` (FTS5) is opt-in. `atlas:tgrep` is advanced. |

## Install

Install Atlas from the marketplace with the APM CLI:

<Code
	lang="bash"
	code={`apm marketplace add sergio-sisternes-epam/atlas-marketplace --name atlas
apm install atlas@atlas`}
/>

The `--name atlas` option is required, so that the package resolves as `atlas@atlas`.

To install one exact release, pin its tag instead:

<Code lang="bash" code={`apm install sergio-sisternes-epam/atlas#v0.13.0-beta.13`} />

APM version ranges skip prerelease tags.
A beta release such as `v0.13.0-beta.13` can only be installed by pinning that exact tag.
Never install from a branch. See [Install](/atlas/start/install/).

Then ask in an agent session: `/atlas How can I get started?`
